# I. 구현 목표

## 분석 주제

제주의 지역별 강수·기온과 날짜별 예보를 비교해 고사리 나들이 준비에 필요한 판단 자료를 제공하고, 개인의 방문·채취·나눔 기록을 다음 활동에 다시 활용합니다. 고사리 발생량이나 채취 성과를 예측하는 학습 모델은 구현 범위에 포함하지 않습니다.

## 해결하려는 불편

관측 자료, 예보, 도매 정산가와 판매 가격은 서로 다른 사이트와 단위로 제공됩니다. 날짜와 위치를 맞추거나 결측을 구분하는 일은 사용자가 직접 해야 합니다. 나들이 이후에는 장소·수량·나눈 사람의 기록이 흩어져 이전 활동을 찾기 어렵습니다.

고사리잇은 질문에 필요한 자료를 선택하고 조건을 맞춰 비교한 뒤, 지도·표·요약과 개인 기록으로 이어지는 작업을 하나의 흐름으로 묶습니다. 분석 결과의 근거는 필요할 때 펼쳐 보고, 첫 화면은 사용자가 이해할 내용에 집중합니다.

## 목표와 확인 방법

| 목표                           | 분석·처리 방법                                        | 확인할 결과                                     |
| ------------------------------ | ----------------------------------------------------- | ----------------------------------------------- |
| 과거 날씨를 같은 기준으로 비교 | 지점·기간·연도 정렬, 유효 관측일 집계, 강수·기온 계산 | 0과 결측 구분, 유효일수와 집계 범위 일치        |
| 날짜·장소 후보 선택 지원       | 강수확률·기온·바람을 선호 순서로 비교                 | 순위, 실제 수치, 비교 이유가 같은 후보를 가리킴 |
| 가격 의미 보존                 | 거래일·규격·등급·가격 종류 분리                       | 다른 단량을 섞지 않고 원자료 단위 표시          |
| 생활 기록 재사용               | 세션별 DB 저장, 지역·공개 근거·지인 연결              | 재방문·수정·나눔 상태 변경 후 같은 내용 조회    |
| 비전문가의 질문 처리           | 모델의 도구 선택, 진행 표시, 간단한 후속 동작         | 질문-도구-답변-상세 결과가 일치                 |

## 센터에서의 활용

센터 방문자는 설치된 브라우저에서 바로 질문하고 제주 관측 자료를 탐색할 수 있습니다. 담당자는 같은 질의를 재현하고 원천·시점·집계 범위를 확인할 수 있습니다. 공개 조회 캐시는 여러 이용자가 재사용하되 개인 기록은 세션별로 분리합니다. 브라우저가 세션을 기억하므로 공용 PC에서는 이용을 마칠 때 ‘개인 기록 초기화’로 세션 기록을 지우고, 보관 기간은 설정(기본 365일)으로 조정합니다. 이용 편의성은 대표 사용 흐름과 좁은 화면 검증으로 확인하며, 대규모 실사용 효과는 운영 후 측정합니다.

# II. 서비스 제안

## 여섯 작업 공간과 대화형 진입점

| 화면      | 핵심 동작                                             | 결과 활용                                   |
| --------- | ----------------------------------------------------- | ------------------------------------------- |
| AI 대화   | 자연어 질문, 도구 진행 확인, 중지, 후속 질문          | 답변의 상세 보기에서 지도·표·비교·조건 변경 |
| 나들이    | 제주 지도와 날짜, 지역·시각 후보 선택, 선호 기준 비교 | 한 후보씩 넘겨 보며 날씨·출처·발표시각·이유·준비물 확인   |
| 지역 탐색 | 주소 검색, 지도 핀, 방문일·메모·별칭                  | 관심 지역 저장, 위치 확인, 관련 기록 탐색   |
| 내 수첩   | 목록·달력, 검색 조건, 별도 작성·수정 화면             | 채취일·수량·위치·메모·공개 근거 보관        |
| 나눔      | 지인 목록·관계별 검색, 지인 상세, 나눔 이력           | 예정에서 전달 완료로 변경, 날짜·단위별 확인, 지인별 공유 파일 |
| 가격 조사 | 가격 종류·날짜·규격 조건, 간결한 결과 행              | 도매 정산·조사·판매 표본을 구분해 비교      |

메뉴 이동은 URL 경로에 반영됩니다. 목록과 작성 화면을 나누고 뒤로 이동할 수 있게 구성합니다. 대화의 조건 변경은 대화 안에서 열리며, 결과는 모달로 확인합니다. 실제 자료가 없는 응답에 빈 결과 카드를 만들지 않습니다.

## 지도 중심의 날씨와 장소 확인

큰 제주 섬 지도에 위치별 날씨 아이콘·온도·강수확률을 표시합니다. 날짜를 바꾸면 같은 화면에서 날씨를 확인하고, 후보 비교에서는 각 지역과 정시를 함께 선택합니다. 현재 위치는 사용자가 허용한 경우 지도 이동을 돕는 데 쓰며 기록 위치를 자동 확정하지 않습니다.

공개 관측 지점은 이름·좌표·고도를 가진 카탈로그로 관리합니다. 예를 들어 한라산남벽을 다시 물으면 같은 공개 지점을 사용해 날씨, 토지 소유구분, 거리뷰 링크를 연결합니다. 토지 분류는 지목이나 국립공원 여부로 추정하지 않고 공식 필지 자료를 사용합니다.

## 개인 기록과 이웃 관계

수첩은 지도 위치·주소 또는 장소 이름을 날짜·수량·메모와 함께 보관합니다. 조회한 공개 자료를 근거로 연결할 수 있습니다. 나눔은 지인을 중심으로 관계와 활동을 관리합니다. 서로 다른 수량 단위를 합산하지 않으며, 지인 변경 후에도 과거 나눔 이력을 보존합니다. 지인 한 명의 나눔 기록은 미리보기와 승인을 거쳐 텍스트 파일 1개로 내려받을 수 있고, 서버에는 파일을 남기지 않습니다.

# II. 사용자 흐름과 UI

## 대표 사용자와 작업

아래 역할은 설계·재현을 위한 합성 페르소나입니다. 실제 이용자 조사 표본으로 해석하지 않습니다.

| 역할           | 시작 질문·과제                          | 완료 흐름                                                                                 |
| -------------- | --------------------------------------- | ----------------------------------------------------------------------------------------- |
| 58세 제주 초보 | 내일 고사리 캐러 가려는데 어디가 좋을까 | 날씨 후보 비교 → 추천·상세 일치 확인 → 한라산남벽 후속 질문 → 같은 지점의 소유구분·거리뷰 |
| 43세 가족 동행 | 가족이 다녀온 장소와 수량을 남기기      | 주소·핀 → 관심 지역 방문일·메모 → 수첩 미리보기·저장 → 목록·달력·수정                     |
| 66세 이웃 나눔 | 누구에게 얼마나 줬는지 확인하기         | 지인·관계 등록 → 나눔 예정 → 전달 완료 → 관계별 이력·공유 파일 → 가격 조회                          |

## 58세 대표 사용자를 기준으로 한 화면

본문과 입력은 16px 이상, 주요 누름 영역은 44px 이상을 기준으로 합니다. 초록 계열 브랜드와 한국어 글꼴을 유지하고, 날짜는 YYYY-MM-DD로 통일합니다. 내부 식별자·원시 JSON·관측 코드보다 지역 이름·날짜·사용자가 할 일을 먼저 보여줍니다.

목록과 달력은 같은 검색 조건과 선택 상태를 공유합니다. 결과가 없을 때 검색 조건 지우기와 새 기록 쓰기를 분리해 제공합니다. 기록의 위치 보기는 읽기 전용으로 열고 실제 변경은 수정 화면에서 수행합니다. 수정 자료를 불러오는 동안 입력을 잠가 늦은 응답이 사용자의 작성을 덮어쓰지 않게 합니다.

## 입력 부담과 이동 부담 줄이기

- 주소 검색과 지도 핀을 함께 제공하고, 핀의 장소 이름을 직접 고칠 수 있게 합니다.
- 작성 중 수첩 초안은 다른 메뉴를 다녀와도 복원하며 명시적인 작성 취소와 구분합니다.
- 음성은 말이 끝나면 인식한 내용을 입력 초안에 반영하고, 사용자가 전송을 누릅니다.
- 후보 결과는 자동 재생 없이 좌우로 이동하며 순위와 전체 개수를 표시합니다.
- 키보드·포커스·모달 닫기, 한글 조합 입력, 좁은 화면의 스크롤을 함께 다룹니다.

대표 흐름은 격리된 합성 세션에서 실제 브라우저로 재현했습니다. 이는 소수의 기능 확인이며, 고령 사용자 현장 사용성 조사나 전체 접근성 인증을 대신하지 않습니다.

# III. Agent 개발 구성

## 역할과 목표

개발자는 데이터 어댑터·분석·저장·UI와 실행 패키지를 구현하고 검증합니다. Agent는 사용자의 공개 질문을 해석해 필요한 도구와 인자를 선택하고, 조회 결과에 맞는 설명과 화면을 구성합니다. 사용자는 불명확한 조건을 보완하고 개인 기록의 저장·변경을 확정합니다.

## 실행 구조

| 단계           | 담당               | 수행 내용                                                       |
| -------------- | ------------------ | --------------------------------------------------------------- |
| 1. 질문·문맥   | 브라우저·API       | 한국어 질문, 허용된 최근 대화, 한국 기준 날짜·시각 전달         |
| 2. 캐시 확인   | 서버·PostgreSQL    | 문맥 없는 동일 공개 질문의 유효한 응답을 첫 모델 호출 전에 확인 |
| 3. 도구 판단   | GPT-6 Luna         | 필요한 Tool/API 선택, 부족한 조건 질문, 후속 질의의 대상 유지   |
| 4. 조건 검증   | 서버               | JSON Schema, 날짜·지역 카탈로그·가격 규격·세션 권한 검사        |
| 5. 실제 조회   | 도구·어댑터        | 기관 자료 취득 또는 유효 캐시 재사용, 정규화·집계·출처 보존     |
| 6. 설명·화면   | 모델·서버·브라우저 | 조회 결과 설명, 등록된 GenUI 구성, SSE로 진행과 답변 전달       |
| 7. 사용자 동작 | 브라우저·개인 API  | 상세 확인, 조건 변경, 수첩 초안·미리보기·동의·저장              |

모델은 질문과 최근 대화, 실제 도구 정의에 따라 호출 여부를 정합니다. 서버는 등록된 도구의 날짜·지역·규격을 검증한 뒤 실행하며, 최종 답변은 조회 결과를 바탕으로 생성합니다.

## 모델·프롬프트·실행 한도

대화 모델은 GPT-6 Luna API를 사용합니다. 의미 캐시의 임베딩은 로컬 multilingual-e5-small이며 리비전을 고정합니다. 프롬프트는 UTF-8 Markdown 파일로 분리하고, 한국 기준 날짜는 요청마다 별도 템플릿에 채웁니다.

기본 실행 한도는 작업당 최대 8단계·64,000토큰이며 모델 동시 호출 수와 대기열도 설정으로 관리합니다. 이 수치는 처리량 보장이 아니라 루프와 비용의 상한입니다. 중지는 같은 작업의 실행 상태와 연결하고, SSE 재접속은 이벤트 식별자로 이미 받은 결과를 구분합니다.

# III. Workflow와 자율 수행 범위

## 공개 조회의 기본 Workflow

“내일 어디가 좋을까?”를 받으면 모델이 날짜·지역·시각을 해석해 후보 비교 도구를 선택합니다. 서버는 공개 위치 카탈로그의 좌표로 기상청 단기예보를 조회하고 강수·기온·바람의 선호 순서에 따라 정렬합니다. 발표 범위(3일) 밖이거나 키가 없으면 Open-Meteo 예보로 대체하고 경고에 출처 변경을 남깁니다. 모델은 실제 순위와 이유를 설명하고, 사용자는 상세 모달에서 각 후보와 준비물을 확인합니다.

“한라산남벽은 어때?”와 같은 후속 질문은 같은 대화의 공개 지점 문맥을 유지합니다. 해당 지점의 소유구분 요청은 좌표 → 지적 필지 → 공식 소유구분 순서로 처리하고, 거리뷰는 같은 좌표의 외부 링크로 제공합니다.

## 개인 기록의 Workflow

수첩·관심 지역·지인·나눔은 폼 작성 → 저장 내용 미리보기 → 사용자 동의 → 실행 결과의 순서입니다. 모델이 개인 작성 폼을 열 수는 있지만 사용자의 확인 없이 저장하지 않습니다. 같은 승인 요청을 재시도해도 중복 기록을 만들지 않고, DB 저장 실패를 성공으로 표시하지 않습니다.

| Agent가 수행하는 일                                      | 사용자가 결정하는 일                                   |
| -------------------------------------------------------- | ------------------------------------------------------ |
| 공개 자료 도구 선택, 조회 조건 구성·검사, 결과 집계·정렬 | 불명확한 날짜·장소·규격 보완, 비교 선호 기준           |
| 등록된 결과 화면·후속 동작 제안                          | 상세 열기, 조건 바꾸기, 외부 거리뷰 링크 열기          |
| 개인 검색 종류·검색어 선택, 작성 폼 열기                 | 위치 핀·개인 본문 입력, 미리보기와 저장·수정·삭제 확인 |

## 개인 본문과 공용 결과의 경계

개인 검색은 같은 세션의 API에서 수행합니다. 모델에는 종류와 건수 등 필요한 최소 정보만 전달하고, 메모·별칭·주소·정확 좌표와 개인 식별자는 상세 화면이 같은 출처의 개인 API에서 읽습니다. 개인 도구가 포함된 턴은 공용 응답·계획 캐시에 저장하지 않습니다.

GenUI는 등록된 컴포넌트와 검증된 결과 참조를 조합합니다. 모델이 컴포넌트와 동작을 고르면 서버가 ResultEnvelope의 참조를 연결합니다. 가격표·지도·비교·조건 폼과 후속 동작은 동일한 카탈로그·레지스트리에서 렌더링합니다.

## 두 층의 공용 DB 캐시

정규화된 공개 도구 결과와 최종 공개 응답을 각각 PostgreSQL에 보관합니다. 같은 질문의 유효한 응답은 임베딩과 모델 호출보다 먼저 확인합니다. 확정된 공개 조건의 의미 검색은 조건이 같고 코사인 유사도가 **0.95를 초과**할 때만 후보로 사용합니다.

지역·날짜·시각·가격 종류·단량·옵션·도구 및 프롬프트 버전을 캐시 범위에 반영합니다. TTL, 출처 상태, 완전성, 내용 해시를 검사하고 실패·불완전 결과는 재사용하지 않습니다. 동시 중복 실행과 한 작업 안의 동일 도구 호출도 병합합니다. 새로운 프로세스와 다른 세션이 같은 DB의 공개 결과를 재사용합니다.

## 비용·진행 상태를 따로 측정

실제 모델 호출 수, 입력·출력·추론·제공사 캐시 토큰과 지연을 작업별로 기록합니다. 공용 응답 캐시 적중률은 제공사의 프롬프트 캐시 토큰 비율과 다른 지표로 집계합니다. 사용량이 없는 응답을 0회로 단정하지 않습니다.

SSE는 도구 시작·완료, 답변 조각, 최종 완료를 전달합니다. UI는 도구 내역을 접어 두고 답변을 먼저 읽게 하며, 완료 전 연결 종료와 정상 완료를 구분합니다. 공개 원천이나 모델 오류는 조회 실패로 처리하고, 캐시·예시 값을 실시간 취득으로 바꿔 표시하지 않습니다.

# IV. 전처리·품질·이용조건

## 원자료의 의미를 보존하는 처리

- 기상: 강수 0과 결측을 구분합니다. 합계·평균·강수일수는 유효 관측일을 함께 계산하고 비교 기간을 맞춥니다. 예보 대상 시각과 관측일·발표 시각을 섞지 않습니다. 후보 비교는 기상청 단기예보의 발표시각을 보존하고 `1mm 미만`처럼 구간으로 제공되는 강수는 수치로 바꾸지 않습니다.
- 가격: 원·kg·포장단위, 생·건고사리, 거래·조사·판매 가격을 분리합니다. 환산 가능한 경우에도 원래 규격을 남기며 자료 없음과 가격 0을 구분합니다.
- 토지: 좌표가 포함된 지적 폴리곤을 확인한 뒤 19자리 PNU로 소유정보를 조회합니다. 경계 중복·인증 실패·자료 없음은 분리하고 공식 명칭을 보존합니다. 개인 소유자 성명·연락처는 수집·보관·모델 전달 대상에서 제외합니다.
- 공통: 요청 범위·실제 취득 범위·취득 시각·관측 기간·파서 버전·출처 상태·내용 해시를 결과에 연결합니다. 이 정보는 상세 근거 확인과 캐시 유효성 검사에 사용합니다.

개발 환경은 Vite 개발 서버와 네이티브 API를 분리합니다. 배포 경로는 웹 정적 파일과 API를 같은 앱 이미지에서 제공하고 PostgreSQL을 별도 서비스로 둡니다. DB 초기화·migration은 관리자 단계에서, 앱의 일상 조회·저장은 앱 역할로 실행합니다.

## 센터 실행환경

공식 최소사양은 Intel Core i7-8700, GTX 1060, RAM 32GB입니다 [R1]. OS가 Windows로 한정된 규정은 아닙니다. 제안 실행 경로는 Linux 컨테이너 기반이며 센터의 컨테이너 실행 허용 여부와 외부 통신 정책에 맞춰 설치합니다. Windows 네이티브 설치와 센터 실장비 동작은 별도 검증 항목입니다.

대화 모델은 외부 API에서 실행하고 센터 PC는 UI·도구·DB·로컬 임베딩을 실행합니다. AMD64 앱 이미지에 고정 리비전의 임베딩 가중치를 포함합니다. 현재 실행 중 작업의 메모리 상태 때문에 worker·replica는 각각 1개를 기준으로 운영하고 DB에 기록을 보관합니다.

## 설정·외부 의존성

API 설정·비밀은 apps/api/.env, 웹 설정은 apps/web/.env로 분리합니다. 제출물에는 예제만 포함합니다. 나눔 공유 파일은 `ALLOW_SHARE_FILE`로 켜고 끄며 예제 설정은 켜 둡니다. 외부 연결 대상은 모델 API, 제주허브·기상청·aT·VWorld, 날씨 API, 지도 타일·주소 검색·지오코딩·거리뷰입니다. 서버 전송 게이트와 브라우저의 지도·주소 요청은 적용 경계가 달라 매뉴얼에 구분합니다. 브라우저 음성 인식은 지원 API와 마이크 권한, 제공사 인식 서비스에 의존합니다. GA4는 정해진 페이지 분류·채팅 이용 이벤트를 집계하며 질문·기록 본문·개인 좌표는 전송 항목에서 제외합니다.

## 용량과 비용 산정 방법

운영 트래픽과 월 비용은 실측 전입니다. 모델 비용은 실제 입력·출력·제공사 캐시 토큰에 계약 단가를 곱해 산정합니다. 도구 호출 비용·기관 쿼터·지도 제공 조건은 별도로 확인합니다. 하나의 대화 요청이 여러 모델·도구 호출을 포함할 수 있으므로 사용자 질문 수를 곧바로 모델 호출 수로 계산하지 않습니다.

저장 용량은 공개 원자료·정규화 결과·캐시와 개인 기록·승인·근거를 분리해 측정합니다. 운영 전 DB 증가량과 보관 정책을 확인하고 백업·복원 절차를 시험합니다. 현재 worker·replica 1개와 제한된 DB 풀을 유지하며, 확장은 동시 실행·DB·작업 복구 검증 후 결정합니다.

## 이후 확장

1. 센터 운영자와 브라우저·네트워크·인증키 설정을 확인하고 동일한 대표 질의를 재현합니다.
2. 도민·가족 사용자를 대상으로 지도·날짜 선택, 기록 작성, 나눔 이력의 완료율을 관찰합니다.
3. 계절별 실제 이용량에 맞춰 캐시 TTL·쿼터·보관 기간을 조정하고 장애 복구를 확인합니다.
4. 충분한 데이터와 평가 설계가 확보되면 개인의 반복 방문 기록을 활용한 탐색 편의를 검토합니다.

센터 제공 가치는 제주 데이터를 일상 질문에서 직접 탐색·비교하고, 같은 조건과 근거로 다시 확인할 수 있는 실행 가능한 작업 공간입니다.
