## 2. 실조회·표본·모델 자료 구분

기상청 초단기실황은 격자 관측이다. 강수 RN1은 1시간 강수로 표시하고 일강수로 합치지 않는다. Open-Meteo는 예보·과거 재분석·모델 현재값을 해당 종류로 표시한다. 다른 출처로 이어서 조회한 결과도 원래 기관 관측으로 바꾸어 표시하지 않는다.

기본 지도는 제주 대표 지역 12곳을 사용한다. 채팅의 공개 지점 카탈로그는 제주데이터허브 578 공식 지점 42곳과 대표 지역을 연결한다. 서버가 공식 좌표를 선택하며, 개인 핀을 공개 카탈로그에 추가하지 않는다.

토지 소유 구분은 공개 지점 좌표로 실제 포함 필지를 찾은 뒤 해당 필지의 공식 분류를 조회한다. ‘국유지’·‘개인’처럼 확인된 분류와 기준월을 사용하고, 법인 등 공공 여부가 확정되지 않는 분류는 공식 명칭을 유지한다. 개인 소유자 이름·연락처는 보관하거나 모델에 전달하지 않는다.

소매와 지역 조사가에는 조사·확인 시점을 붙인다. 예를 들어 2026-11-04 표본의 제주 생고사리 상 조사가와 상품 200g 표시가는 그때 확인한 표본이며, 최신 자동 취득 가격과 구분한다. 표본 안의 산지명 0건은 해당 조회 범위의 결과다.

## 3. 품질 처리와 보관

- 강수·기온의 숫자 0, 결측, 오류, 의미가 확정되지 않은 공란을 구분한다.
- 같은 키의 동일 중복은 한 번 집계하고, 서로 다른 값의 충돌은 구분해 반환한다.
- 비교에는 항목별 유효 날짜와 공통 날짜를 사용한다. 기온과 강수의 유효 범위는 각각 계산한다.
- 가격은 생건·산지·등급·포장·중량·배송·쿠폰 조건을 구분한다. 원래 가격·단량·환산식과 1kg 환산값을 함께 보존한다.
- 기관 실조회의 정규화 결과·조회 조건·요청/취득/실패 범위·행수·시점·원 응답 해시·처리 버전을 공개 근거와 연결한다. 제공된 검증 표본은 `fixtures/`에서 관리한다.
- 정규화 공용 조회 캐시는 출처 메타데이터·내용 해시·버전·TTL·품질 상태를 검사한다. 응답 캐시는 질문 조건·모델/프롬프트/도구 버전과 답변 무결성을 별도로 검사한다.
- 지도 화면의 Open-Meteo 조회는 날짜별 5분 캐시를 사용한다. 대화·분석용 PostgreSQL 공용 캐시와 구분한다.

## 4. 개인 자료 경계

수첩·관심 지역·지인·나눔은 세션별 개인 테이블에 저장한다. 모델의 개인 검색 도구는 종류와 건수만 받으며 실제 기록은 같은 출처의 개인 API로 화면에서 읽는다. 개인 원문·별칭·기록 ID·개인 좌표는 공용 응답·계획 캐시에 넣지 않는다. 공개 근거에는 개인 수첩으로의 역매핑을 저장하지 않는다.

주소 검색·좌표 변환은 사용자가 선택한 주소를 외부 주소 서비스로 전송한다. 브라우저 음성 인식 서비스는 제공사 원격 처리를 사용할 수 있고, 앱 서버는 음성 파일을 받지 않는다. GA4에는 고정 페이지 이름과 채팅 동작 종류만 전송한다. 상세 흐름은 [AI·외부 서비스 목록](ai-and-dependencies.md)에 있다.

## 5. 제출 자료와 재현

제출 소스에는 검증 표본·코드·잠금 파일·앱별 환경변수 예제를 포함한다. 실제 API 키·`.env`·개인 DB·개인 브라우저 저장소는 포함하지 않는다. 실조회는 평가 환경의 기관 활용신청·키·네트워크로 재현하고, 표본 재생은 그 시점과 범위를 유지한다.

최신 제출 실행본 검증과 이전 개발 실조회는 [구현 결과](submission-results.md)에서 구분한다. 과거 인수표의 수치는 당시 기준이며 현재 실행본의 전체 통과 수로 사용하지 않는다.
